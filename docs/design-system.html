& Placement Planner — Design System

Living reference · for the design pass

The paper, the palette, the pieces.

This is the working design system for a couple's private wedding placement & seating planner. Every token and component below mirrors src/app/globals.css by the same name — so a refreshed globals.css restyles the whole app with little component churn. Treat this as the canvas: keep the class names, elevate everything else.

01 · Direction

An editorial, wedding-stationery feel

Warm ivory paper, ink text, an antique-gold accent, and a serif display face paired with a clean sans. It should feel personal and celebratory — fine paper and letterpress, not a corporate dashboard — while staying calm and highly usable on a phone. The couple are the only two users; the voice is warm and plain-spoken ("Mark purchased", "Seat party here").

03 · Typography

Cormorant Garamond & Inter

A high-contrast serif for display (headings, numbers, table names) and Inter for everything operational. Display is set through the .font-display class; the uppercase tracked label is .eyebrow. Fonts are self-hosted in the app via next/font — propose replacements as next/font families.

Spacing rhythm

Layout uses flex/grid gap on a 4px base (0.25rem steps). Generous section padding (2.5–3rem), comfortable card padding (1rem–1.5rem). Keep running text ≈ 60–70 characters wide.

06 · Domain patterns

Tables, seats & parties

The spatial heart of the app: round/rectangular tables with seat squares on a venue map, seats that fill as guests are placed, and party colors that tie linked guests together. This is where the most design attention would pay off.

07 · What to elevate & how it maps back

Your brief, in one place

Where the most design attention pays off

  • A refined type scale and heading rhythm — make the serif sing.
  • A cohesive icon set (nav + actions: add, edit, delete, drag, search, import/export, print).
  • Illustrations for empty states (no items / no guests / nothing placed) and a login hero; light botanical dividers.
  • Table & seat treatment on the venue map — occupied vs open, party color, the split-party warning.
  • A wordmark, favicon, and OG image.
  • Elevation, focus states, and motion (tasteful, reduced-motion aware).

How outputs fold back in

  • Tokens + components → src/app/globals.css. Keep these class names (.btn, .card, .input, .chip, .meter, .font-display, .eyebrow) and the token names — then the whole app updates with no component edits.
  • Fonts → src/app/layout.tsx (next/font families + --font-* vars).
  • Assets → public/ (SVG); icons as small inline-SVG React components under src/components/icons/.
  • Favicon / OG → src/app/icon.svg and src/app/opengraph-image.*.

Constraints: Tailwind v4 tokens in @theme + components in @layer components; both themes; WCAG AA; self-contained (no runtime CDNs); mobile-first; no new deps without flagging.
